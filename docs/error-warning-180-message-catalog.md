# Specialized error and warning message audit

Source snapshot: 2026-09-27. Run `node scripts/error-warning-audit/count-specialized-messages.cjs` to recount. This is a source inventory, not a production-browser verification. It must not be used to claim release completion.

The separate [production browser audit](evidence/production-error-audit/README.md) records which roles and failures were actually exercised through the deployed app, the isolated QA records left for follow-up, and the candidate fixes prompted by those observations. Later [Supplier time-batch](evidence/error-warning-supplier-time-batch-production-20260926.md) and [Owner billing issuer](evidence/error-warning-billing-issuer-production-20260926.md) production checks found retained-hours/focus gaps and a generic issuer-validation response with an unrelated invoice-issue banner, respectively. A separate [candidate Planning and Document recheck](evidence/error-warning-candidate/next-wave-focus/README.md) passed four native-form focus and retention cases at 390 and 1440 px; it does not cover the new Crew or Supplier mappings.

[Independent disposable Chromium evidence](evidence/error-warning-candidate/login-rate-limit-independent-browser/README.md) passed the real sign-in 429 flow in EN/ES/PT at 390 and 1440 px, including visible focused countdown, retained entries, and no fourth POST. [Independent notification evidence](evidence/error-warning-candidate/notification-independent-browser/README.md) passed Worker, Manager, and Owner stale-detail recovery with a focused role-safe inbox remedy. These QA results do not themselves add codes to the 619 literal-source count below.

Help PDF downloads now return four typed problem codes for sign-in, unavailable guides, unsupported languages, and temporary download failure, while retaining the prior localized `error` field. The Help page focuses its visible failure explanation. [Production baseline and independent candidate Chromium evidence](evidence/error-warning-candidate/help-browser/README.md) cover real 401/400/404 responses, permitted PDFs, and intercepted 401/404/503 UI recovery for Worker, Manager, and Finance at 390 and 1440 px. Private document and report-attachment GETs now have nine counted literal codes for sign-in, unavailable or concealed records, file readiness and integrity, and service failures. The Documents-list client now handles failures beside the originating row; [independent disposable Chromium evidence](evidence/error-warning-candidate/private-document-candidate-browser/README.md) covers typed failures and authorized downloads in EN/ES/PT at 390 and 1440 px. [Billing, ledger, and private-PDF browser evidence](evidence/error-warning-candidate/billing-ledger-document-browser/README.md) covers localized warnings, focused inline invoice/report PDF failures, real 401/404/409 route responses, and headed Chromium PDF preview success after the SvelteKit CSP fix. Its 503 UI cases were intercepted; ledger no-rows and undated states were not reached through the permitted UI. These GET checks do not verify every role or failure state.

## Counting rule

- **181 actions** in the separate [form action inventory](error-warning-action-inventory.md) are routes/actions, not messages.
- **619 distinct code and message-key pairs** and **619 stable codes** appear as literal typed descriptors or `actionFail` calls in portal action and route TypeScript. The recount includes nine private-document and report-attachment GET codes. All 619 pairs have explicit English, Spanish, and Portuguese catalog text; it found no code collisions or untranslated pairs. This is translation presence, not linguistic or browser quality.
- The source counter does not include codes passed through the Accounting Pack, worker statement, report attachment, document, expense lookup, billing, and Finance action-family problem factories when code and key are selected dynamically. Their focused contract tests and browser evidence are tracked separately; do not add them to the 619 count without extending the counter. The new direct GET route descriptors are included because their codes and keys are literal.
- **447 pairs** include a literal remedy ID in the same descriptor. The intentionally narrow state-specific filter removes codes containing `INVALID`, `FIELDS`, `INPUT`, or `REQUEST`; it leaves **347 distinct state-specific codes** as review candidates. This exceeds the numerical 180 target, but every row still needs runtime, role, and wording verification. Simple required-field messages can remain useful yet are excluded by this narrow count only when their code matches the filter.
- Supplier messages are often terse and still need copy improvements. Excluding that entire domain leaves **275 codes and 255 distinct English wordings** in the state-specific/remedy subset. This guards against inflating the count with duplicated copy; it still does not certify the wording, production reachability, or role-safe remedies.
- No translation variant, repeated occurrence, status badge, generic failure, or proposed future warning is counted as an additional message. An unknown exception code is not a specialized business message.

## Findings that block a verified 180-message release claim

- **Production reachability is unknown.** The table proves definitions exist in this checkout. It does not prove that the current production build contains them, that the triggering state reaches the mapper, or that the visible component renders the translated text and remedy.
- **Role-safe remedies are unverified.** Several descriptors share broad `contact_project_owner`, `review_*`, or `correct_*` IDs. Browser tests must confirm that links exist only for permitted roles and preserve form values, focus, tab, and scroll.

Their literal action descriptors contribute to the 619-pair source count, but the narrow 347-candidate table is dominated by supplier, crew, access, time, and project domains. Audit finance and billing runtime branches for cause, permitted next step, and role-safe links.
- **Warning coverage remains incomplete.** The assignment picker, twelve consequence decisions, and four Reports detail decisions now use typed `ProblemNotice kind="warning"`.
