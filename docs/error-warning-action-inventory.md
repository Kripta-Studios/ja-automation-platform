Generated from route `actions` declarations, the `/app/[section]` delegation map, and the supplier action factory on 2026-09-25. This is a route-level inventory, not proof that every business branch has a final code. The “Role scope” column is a review target inferred from the action area; server guards and object scope remain authoritative. Rows marked **Gap** are not release-complete.

**Count:** 180 named/default actions across 15 route patterns. The shared /app/[section] route delegates to the source action named in each row.

Current generic fallback means the body reaches `actionFailure` or its shared wrapper. This includes known business exceptions until their branch is mapped to a stable code. An empty explicit-key cell means the action delegates validation or returns another response shape.

## Current mapping audit

The shared `actionFail` path supplies a serializable code, parameters, field errors, remedies, and correlation ID. A code derived from a generic key does not prove that a known business blocker is explained. Known-error mappers cover listed repository messages; their final `actionFailure(error)` branch remains necessary for unforeseen exceptions. Those exceptions should keep the safe reference message. A known conflict that reaches that branch is a release gap.

### Prioritized residual gaps

1. **Project detail actions:** [Project detail](../apps/portal/src/routes/app/projects/[id]/+page.server.ts#L221) has seven actions with generic validation keys and direct generic `actionFailure` catches. Milestone, people terms, billing setup, invoice draft, update, and delete need explicit stale/state/configuration maps. Several schema failures provide raw `flatten().fieldErrors`; verify field-local localization and preserved values.
2. **Remaining direct routes:** [Period report review](../apps/portal/src/routes/app/reports/period/[id]/+page.server.ts#L167), [report detail](../apps/portal/src/routes/app/reports/[id]/+page.server.ts#L90), and [expense detail](../apps/portal/src/routes/app/expenses/[id]/+page.server.ts#L88) still have generic direct validation or catch paths. Audit stale review, signed/final report, correction-draft, and submitted-expense messages against each repository throw. An unknown exception may remain generic; a known business state may not.
3. **Field error language:** [The shared field renderer](../apps/portal/src/lib/portal/ui/form-validation.ts#L76) translates common Zod diagnostics, then translates unknown raw text as a key. Many handlers pass [`flatten().fieldErrors`](../apps/portal/src/lib/server/actions/finance-actions.ts#L341) through. Custom schema/refine text such as [availability pairing and date order](../packages/schemas/src/index.ts#L270), and hard-coded custom `fieldErrors`, need explicit catalog keys or verified English, Spanish, and Portuguese entries.
4. **Unmatched mapper branches:** [Supplier](../apps/portal/src/routes/app/supplier/+page.server.ts#L512), [crew](../apps/portal/src/routes/app/crew/+page.server.ts#L319), [access](../apps/portal/src/lib/server/actions/access-actions.ts#L163), [time](../apps/portal/src/lib/server/actions/time-actions.ts#L271), [expense](../apps/portal/src/lib/server/actions/expense-actions.ts#L287), [reports](../apps/portal/src/lib/server/actions/operations-actions.ts#L249), [approval](../apps/portal/src/lib/server/actions/approval-actions.ts#L7), [billing](../apps/portal/src/lib/server/actions/billing-actions.ts#L237), and [Finance](../apps/portal/src/lib/server/actions/finance-actions.ts#L38) each map a set of known messages. Compare remaining repository messages and role-safe links with browser traces. Preserve the generic fallback for genuinely unforeseen errors.

Closeout now maps the five mutation actions to stable codes and role-safe remedies, with a required compare-and-swap guard for stale refreshes. Notification detail now gives invalid or missing notification IDs an inbox remedy. Both changes await the final candidate browser pass.

The previous raw confirmation/profile failures in manage and supplier, and schema/range failures in Finance preview, now use `actionFail` with explicit codes or field errors. The assignment status conflict has focused phone and desktop browser evidence; that evidence does not close the wider inventory.

## Recovery policy

Mechanical normalization (such as trimming harmless whitespace) and refreshing option lists may run without changing user intent. Retry a mutation only when an idempotency key proves it safe. For uncertain saves, inspect the created record before suggesting another submission. A stale record needs a review path and a description of the changed state. Never silently reopen a project, approve time, submit a draft, alter reimbursement or tax treatment, change an invoice, or overwrite another edit.

## Release audit

For each row, verify every known domain blocker has a stable code, localized cause, role-safe remedy, retained form values, and focused browser evidence. Unknown technical exceptions must show only a safe reference ID. “Generic fallback” is an audit cue, not a claim that every current fallback is a known business case.
