# Independent pre-deploy review — 2026-09-25

**Verdict: FIX-FIRST** for the candidate inspected against `/opt/jaautomation/current` on 25 September. This review covers the browser-swarm remediation diff, not the many pre-existing dirty worktree changes. No production write or deployment was performed.

## Material blockers

1. **Empty hourly labor period offers a Save action that the server rejects.** The wizard's special empty state applies only to expense streams ([BillingSection.svelte](../../apps/portal/src/lib/portal/sections/BillingSection.svelte), lines 200–205), so a labor stream with `includedSourceCount=0` can display `Ready` and enable Save (lines 980–990, 1161–1189). Repository readiness can return `ready` for such a period ([repository.ts](../../packages/database/src/repository.ts), lines 4930–4980, 5073–5083), but draft creation rejects a zero subtotal with `no_billable_sources` (line 5573). A fixed-price or hybrid labor stream can legitimately produce a positive fixed fee without time sources (lines 5282–5309); distinguish that case when fixing the wizard. Add a focused regression for a zero-source hourly stream and a fixed-fee stream.
2. **Revoked Crew records can remain listed, and regrant can revive an old draft for direct submit.** Crew detail requires the record's original grant ID ([crew-leader-repository.ts](../../packages/database/src/domains/workforce/crew-leader-repository.ts), lines 457–481), and a new grant can be issued after revocation (lines 345–369). `entries()` checks only recorder, project and date (lines 422–454). The route admits the project when *any* current Crew grant exists, then calls `entries()` ([Crew +page.server.ts](../../apps/portal/src/routes/app/crew/+page.server.ts), lines 53–72). Thus if the chief retains another worker's grant for that project, the list can disclose the revoked worker's name, time and summary and offer a detail link that denies access. The new detail Submit action reaches `crew.submit` ([Crew detail +page.server.ts](../../apps/portal/src/routes/app/crew/time/%5Bid%5D/+page.server.ts), lines 48–50); `crew.submit` checks recorder identity but does not compare the recorder grant ID (crew repository lines 785–794). The time submit path accepts any currently effective delegated grant ([time-entry-repository.ts](../../packages/database/src/domains/time/time-entry-repository.ts), lines 266–290, 380–448). After revoke then regrant to the same recorder and worker, a direct POST can therefore submit an old draft that Crew detail refuses to show. Apply consistent exact-grant checks to list and submit, and test revoke with another active project grant plus revoke → regrant → old-draft denial. These paths are source-proven; I did not execute the sequences in a fixture.
