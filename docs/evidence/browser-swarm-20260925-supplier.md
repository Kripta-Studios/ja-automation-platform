## Verified behavior and UX notes

- The Supplier Coordinator can create, edit while Draft, and submit a delegated entry. The status survives reload. On mobile, the list scrolls to the saved row and the document has no horizontal overflow. After both Save and Submit, focus rests on `<body>` rather than the result heading or a status message. This is an accessibility/feedback improvement, not a blocker observed in the visual flow.
- Owner's 390 px Approvals action menu opens and accepts a required reason. The returned reason appears on both canonical Time and supplier Crew detail. After Needs changes, the action queue no longer includes the item; this is expected if returned items are managed through their source lists, but the Crew list currently offers no correction action.
- The Supplier Coordinator receives a clear role-specific 403 on canonical `/time/{id}`. This denial itself is correct; the broken promise is the Crew detail's instruction to use a worker login that does not exist.
- A read-only 390 px check used saved sessions for Supplier Coordinator, External Technician, Worker 2 (crew chief), Project Manager and Auditor. The supplier could read its operational report and the returned Crew detail; the external technician could read its supplier report but had no access to this other technician's time; Worker 2 could not read this supplier record; Project Manager and Auditor could read the canonical Time detail but had no correction controls. These outcomes survived separate page loads, and none of the 15 checked views overflowed horizontally. Evidence: `target-matrix.json`, `supplier-report-returned-390.png`.
