# Browser action audit — 30 September 2026

## Scope and method

This is the ongoing follow-up to the [deployed seven-role audit](../live-browser-audit-20260929/README.md). The current round creates all new mock business records through visible browser forms. It uses an isolated copy of existing production data and private files, a candidate running the changed source, independent Chromium contexts, runtime request/status and console capture, and CDP for browser-device checks. No new business records are seeded through SQL, repository helpers, or direct API calls.

GPT-6 Luna agents test operational and financial role journeys. GPT-6.1 Sol implements fixes and independently reviews material security changes. Raw sessions, credentials, invitation tokens, authenticator secrets and customer records remain private and are excluded from Git and the deployment archive.

Actual email delivery uses the app's real signed HTTPS outbox worker and TLS SMTP into an isolated capture mailbox. An invitation created through Owner UI was delivered, opened from the captured message, activated through its visible link and used for a successful browser login. Production SMTP/DNS and unrelated containers were not changed.
