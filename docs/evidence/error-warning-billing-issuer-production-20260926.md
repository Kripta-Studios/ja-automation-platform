# Billing issuer validation — production browser check, 2026-09-26

The deployed Owner portal was tested through Playwright browser MCP at 390 × 844. An existing issuer explicitly marked TEST ONLY was used. No real issuer was edited, and the failed submission did not save the test value.

| Check             | Observed production result                                                                                                                                                                                                                                                                     |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Route and role    | `/j-aautomation/app/billing`, Owner, Configure billing → Invoice issuers → Edit issuer.                                                                                                                                                                                                        |
| Trigger           | Replaced only the optional tax/registration identifier with 1,001 harmless characters; selected Save issuer. Other fields retained their existing test values.                                                                                                                                 |
| Network           | Native `POST ?/updateLegalEntity` returned HTTP 400. Response carried generic code `ACTION_ERROR_INVALID`.                                                                                                                                                                                     |
| Visible failure   | In-editor “Action needed” notice said “Check the submitted values and try again.” It did not identify the overlong identifier or its 1,000-character limit, and offered no correction remedy. A separate top “Invoice issue blocked” alert appeared, although this was an issuer setup action. |
| Recovery          | The editor remained open; the 1,001-character input and other fields remained; Configure billing stayed selected. Focus moved to the in-editor notice. The notice was visible near the top of the 390 px viewport (about 67–353 px); scrollY remained about 1,425.                             |
| Console           | One resource-load error corresponded to the expected HTTP 400; no separate client exception or warning.                                                                                                                                                                                        |
| Persistence check | After a fresh navigation and reopening the TEST ONLY issuer, the original 40-character identifier was still saved. The 1,001-character test value was absent.                                                                                                                                  |

Candidate source already has a mapping for this exact domain validation to `BILLING_ISSUER_IDENTIFIER_TOO_LONG`, with field guidance to shorten the identifier to 1,000 characters or fewer. Browser QA must confirm that candidate behavior before release. The separate invoice-issue banner should be restricted to invoice issue/readiness failures; issuer setup validation must not present it.
