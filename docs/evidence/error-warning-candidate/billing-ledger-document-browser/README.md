# Billing, ledger, and Documents browser QA

All interactions used a disposable local SQLite fixture and a locally built portal preview on port 4174. No production record was changed. Browser contexts used the real login form for Owner and Finance. Screenshots are cropped to warning or error notices and contain no document bytes or account identifiers.

## Source and method

- Initial preview: product `e89e7fa`. The read-only billing and ledger pass found raw catalog keys in EN, ES, and PT. `before-catalog-fix.json` records the visible text, links, focus, viewport geometry, field retention, and network/console metadata.
- Corrected preview: product `1866755`. The same browser flow at 1440 px Owner EN, 390 px Finance ES, and 390 px Owner PT found translated no-tax and filtered-empty warnings. `after-catalog-before-scroll-fix.json` records the actual UI. The tax-profile remedy reaches the setup control without clearing the selected project or recipient email. The ledger search survives Apply filters.
- Final warning preview: product `6632e15`. `final-ledger-billing-6632e15.json` and six notice-only PNGs show the EN/ES/PT warnings. After the real Apply filters GET and 1.2 seconds for navigation to settle, the filtered-empty notice was focused and within the clear viewport at 1440 and 390 px. The 390 px safe bottom was 764 px, above the fixed navigation; the notice ended at 508 px. Search text and Billing form project, stream, and recipient values remained entered. The tax-profile remedy anchor remained visible and preserved entries.
- Documents: on initial `e89e7fa`, Owner at 390 px PT middle-clicked View. A typed 404 was intercepted at the private GET boundary. `document-middle-click-pt-390-404.json` and the notice-only PNG show the localized cause and Review Documents remedy; the notice received focus, the Documents page stayed open, and no raw JSON tab remained. This interception tests UI handling, not a real missing file.
- Invoice PDF on `6632e15`: real browser GETs returned typed signed-out 401, Owner pending 409, and Worker 404 with role-safe `contact_finance`. A disposable issued invoice was moved through the allowed PDF-ready metadata transition using renderer-produced bytes stored only in the disposable document root. The UI then received real 200 PDF responses for inline, Open, and Download; the browser Download event produced a PDF filename. Intercepted typed 401/404/409/503 on the visible invoice page produced localized EN/ES/PT, focused inline notices with permitted remedies and no raw JSON tab. See `invoice-pdf-pre-6632e15.json`, `invoice-pdf-ready-6632e15.json`, and the four cropped notice PNGs.
- Report PDF on `6632e15`: real browser GETs returned typed signed-out 401, Worker internal-report 404, and Owner unready 409. A disposable internal report was rendered and stored with matching hash/length; its real Open GET returned 200 PDF. Intercepted typed 401/404/409/503 on the ready report page produced localized EN/ES/PT, focused notices, current report status, permitted remedies, and no raw JSON tab. See `report-pdf-pre-6632e15.json`, `report-pdf-ready-6632e15.json`, and the four cropped notice PNGs.
- The `6632e15` PDF success run exposed a real preview defect: Chromium blocked the verified `blob:` PDF iframe under the portal CSP (`default-src 'self'`, no `frame-src`). Invoice inline preview and report popup preview therefore remained blank despite 200 responses and visible frames. Download succeeded. The relevant console diagnostic is redacted in the invoice/report JSON. `invoice-csp-bfaab3a.json` confirms that a first patch to the fallback header did not change SvelteKit's HTML CSP: the frame still navigated to `chrome-error://chromewebdata/`.
- Final PDF preview rerun: clean built product `2492d0e`. The actual HTML response included `frame-src 'self' blob:`. Headed Chromium under Xvfb then rendered `blob:` child frames with MIME `application/pdf` for invoice inline, invoice Open, and report Open at Owner EN 1440 px, Finance ES 390 px, and Owner PT 390 px. Every artifact GET returned 200 `application/pdf` with attachment disposition; the original invoice/report tab stayed open, fallback Download links were visible, invoice Download produced a PDF filename, and page/popup console errors were empty. `artifact-success-2492d0e-headed.json` records frame protocol/MIME rather than private URLs or PDF content; the six fallback-link PNGs crop out the document.
- Headless Chromium did not render its built-in PDF viewer even with the corrected CSP: its child frame stayed empty HTML while logging no CSP error. `artifact-success-2492d0e.json` records that tooling limitation. The headed rerun above is the rendering verification.
- The preview's offline identity endpoint returned 503 in this disposable environment. Browser console/page errors were empty in these cases; the 503 is captured in the JSON metadata and did not affect the warning flows.

## Remaining checks

- The first corrected preview moved the focused filtered-empty warning offscreen after navigation restored scroll. The `6632e15` browser rerun above verifies the subsequent focus/scroll fix.
- The undated ledger branch was not browser-verified. The normal UI stamps an issued invoice, and the disposable database's `issued_invoice_snapshot_no_update` guard rejected a temporary attempt to remove issue dates. The transaction rolled back; no invoice changed. The guard was left intact.
- The no-rows ledger branch cannot be reached through the seeded Owner/Finance UI without changing all authorized issued invoices. Keep that as an explicit browser coverage limit. The filtered-empty branch was exercised through the real search form.
