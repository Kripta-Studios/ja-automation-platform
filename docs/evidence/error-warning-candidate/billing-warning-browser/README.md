The mobile archive warning is cramped by the stream table layout. Read-only reruns at 390 px in EN and ES show the warning at 117 and 122 px wide respectively, within `.billing-section__rule-actions` (146/151 px), `.billing-section__rule-editor` (146/151 px), and a `td` (168/173 px). The table itself is 424/436 px wide inside a 327 px `.billing-section__rule-list`; scrolling the notice into view shifts the page horizontally. PT cropped notice was about 115 px wide. This is a layout defect across the three tested locales. See `archive-geometry.json` and the two `finance-archive-stream-phone-{en,es}-geometry.png` crops.

No browser `pageerror` exceptions were observed in these cases. The browser reported a separate HTTP 503 resource failure on page load; that was not associated with a form POST and was not investigated in this bounded warning check. Screenshots crop only the notice, with no account or record identifiers. The JSON records no passwords, fixture tokens, invoice IDs, or full network bodies.

## Candidate follow-up checks

The cramped 390 px archive notice above is a **pre-fix diagnostic**. A scoped mobile stream-card layout was added and the independent Chromium rerun measured a 264 px notice and a 390 px document in EN/ES/PT; see [independent QA](../billing-independent-browser/README.md). A fresh automated suite then passed 8 substantive Billing cases at 390/1440 px, with 8 intentional viewport skips. It covered linked-source and invoice-line blockers, allowed UUID draft and approved discards, archive guidance, historical text-ID issue-marker controls, and a native typed 409 with no invoice or audit write. See [reduced automated result](automated-results.json).

The later selected-invoice remedy correction was tested separately in actual Chromium; its post-fix result is recorded in the independent QA packet. These checks used disposable candidate data and did not deploy to production.
