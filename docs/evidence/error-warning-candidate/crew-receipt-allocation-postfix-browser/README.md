# Crew shared receipt allocation: independent post-fix browser QA

Frozen candidate product commit: `3599b9812ea0172f7e97658020026354e2ba7e7c` (tree `3b54a9d7693f69676e6199564577710fb1accbdc`). This evidence-only worktree is independent of the implementation worktree.

Actual Playwright Chromium ran against a fresh disposable database. Owner used the app to create a project and grant a chief two workers. The chief used the app to save both time rows and a draft expense with a synthetic PDF receipt. Two chief tabs then opened the same Crew date. Tab A entered **7.00 + 5.50**; Tab B saved **8.00 + 4.50**. Tab A sent its stale form values through a SvelteKit enhanced action-envelope request and a native browser form submission.

The remedy is role-safe: it links within the chief's Crew page to the exact saved allocation anchor and includes the receipt query. The test **clicked it** and verified that a full reload retained the current language and landed on a present saved allocation anchor. The link has no explicit `lang` parameter, but the phone remained `en-US` with the “Saved receipt allocations” heading, and desktop remained `es-ES` with “Distribuciones de recibos guardadas.” Project, date, and locale stayed selected on the failed page. Owner and both chief tabs had no page exceptions or console errors.
