# Expense draft receipt warning: independent Chromium check

Candidate: `cacd8d0aefb48e23d59cc98e2d8758e452f7a55a`. The test used a fresh disposable SQLite fixture and the built portal on local port 4174. No production request was made. The Owner created an active project and Worker assignment through the portal. The Worker selected a project offered in their own expense picker. The test submitted only disposable expenses.

The enhanced invalid-amount response was transport HTTP 200 with SvelteKit failure status 400 and ProblemData `code=EXPENSE_AMOUNT_INVALID`, `messageKey=problem.expense.amountInvalid`, `params={}`, `fieldErrors={amount:[problem.expense.amountInvalid]}`, `remedies=[{id:review_expense}]`. The rendered remedy said **“Review updated record”**, which does not tell the user to correct the amount. This is a separate remedy issue; the receipt warning itself was nonblocking.

The warning screenshot crops show a generic **“Sync failed — retry when the connection is stable”** toast covering part of the warning. In the Owner English crop it covers nearly all of the warning. The DOM and `results.json` confirm the warning text and visibility, but the screenshots do not establish unobstructed visual readability. The toast did not appear as a browser console or page error in this run. See the three `*-warning.png` files for the actual overlap.

`results.json` contains the redacted browser snapshots, network status and content type, warning and field values, focus, scroll, audit checks, and empty page-error/console-error arrays. `receipt-warning.spec.ts` and `playwright.config.ts` reproduce the check. No business record IDs, login details, or full-page personal data are included in the evidence.
