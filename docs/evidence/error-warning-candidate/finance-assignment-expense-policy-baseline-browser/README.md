# Finance person expense policy: stale assignment browser baseline

Candidate product commit: `a21d12d0383b149170da7a6d3faad70bde37a5b2`.

The test uses actual Playwright Chromium and a fresh disposable SQLite fixture. Owner (1440 × 900, English) creates an Active project with an open-ended worker assignment through the Projects form. Finance (390 × 844, English) opens **Finance → Commercial → Person expense policies** and enters a policy. Owner then changes that assignment's end date to **2026-10-15** through the rendered Update assignment form. No production account, database, or deployment is used. The stored result is a sanitized network and UI trace; screenshots crop only the problem notice. The disposable fixture is removed when Playwright exits.

On the 390 px phone, the stale date case focuses a validation summary at y=86 while the main notice is at y=-2727. The bounded case focuses the end-date input at y=85 while its notice is at y=-3242. The sticky header ends at y=70. Neither case produced a page exception or console error. The form submission changed the user's scroll position from 3793 to 3275 in the stale case. These coordinates were recorded before taking locator screenshots, since screenshots can scroll elements into view.

The repository also maps `Active project assignment required` to `FINANCE_POLICY_ASSIGNMENT_UNAVAILABLE`. A separate attempt to remove the assignment through Owner's nested Projects control stalled opening that control, so this baseline does **not** claim a browser observation for the unavailable case. The failed optional raw Playwright trace remains untracked and is not part of this redacted evidence.
