# Project lifecycle warning browser QA

Actual Chromium against an isolated disposable Portal preview on candidate parent `13dd71a` with six reviewed warning overlay paths. This run completed the lifecycle checks before a host interruption ended the preview. It did **not** complete Supplier Coordinator warning submission checks.

Owner at 390 px in English and Finance at 1440 px in Spanish opened separate active synthetic lifecycle projects in the rendered project register. Each saw `WARNING_PROJECT_LIFECYCLE_ASSIGNMENTS` before **Begin close** and again before **Close project**. The warnings said that new assignments are unavailable in Closing or Closed status and offered links to review project status and assignments. Owner’s assignment link opened authorized controls; Finance’s link went to assignment history without exposing assignment settings.

Read-only database checks found no project status or version change while either warning was merely displayed. After the authorized user entered a reason and submitted, each native form returned HTTP 200 and the relevant project moved active → closing → closed. All four notices fit inside the tested viewport after scrolling to them; passive warnings did not take keyboard focus. No JavaScript page exceptions occurred. The preview emitted two expected 503 offline-identity failed-resource lines per browser context.

[Redacted observations](lifecycle-results.json) contain warning codes, localized wording, remedy paths with fixture IDs removed, geometry, action statuses, and status changes. The cropped screenshots show only synthetic-project warning text: [Owner Begin close](lifecycle-phone-390-closing-notice.png), [Owner Close](lifecycle-phone-390-closed-notice.png), [Finance Begin close](lifecycle-desktop-1440-closing-notice.png), and [Finance Close](lifecycle-desktop-1440-closed-notice.png). No credentials, account addresses, real customer data, or raw fixture IDs are stored.

Supplier UI setup had created a synthetic supplier, coordinator/external-technician profiles, an active grant, and one technician assignment before the host interruption. The assignment harness missed its response after the write, so it was not repeated. No Supplier draft or submission warning evidence was captured. The old fixture was explicitly released for cleanup and a fresh isolated browser spec.

## Final automated continuation

After the host interruption, a fresh isolated fixture ran [`project-supplier-warning-browser.spec.ts`](../../../../tests/e2e/project-supplier-warning-browser.spec.ts) in actual Chromium with the final scoped menu-width fix. All five substantive cases passed at 390/1440 px; five nonmatching viewport instances were intentionally skipped. The suite covered Owner and Finance lifecycle warnings and Supplier Coordinator single/batch submission warnings in EN/ES/PT. It asserted localized consequence text, role-appropriate remedies, full-document horizontal fit, no write before explicit submit, and the expected state transition after submit. [Reduced result](automated-results.json) contains no fixture IDs or account data.

The first desktop diagnostic found page `scrollWidth` rising from 1440 px to 2303 px when a lifecycle menu with warning opened; hiding the warning returned it to 1440 px. A scoped menu/form width fix kept the open menu and warning within the viewport. The final suite passed the full-document overflow assertion at both widths. The earlier manual Supplier check remains incomplete, as recorded above; the fresh automated browser suite provides the Supplier result.
