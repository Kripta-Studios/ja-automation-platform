Actual headless Chromium on 27 September 2026 against a separate disposable candidate Portal preview based on `c4984ee`. Owner created a synthetic project, assigned a Worker, and created two daily draft reports through the rendered web forms; those creation POSTs returned HTTP 200. Seeded approved reports were used only inside the disposable database. No production account, record, or deployment was touched.

## Repeat report edit returns HTTP 500

On the first synthetic draft, an Owner's initial Save changes returned HTTP 200 and advanced the report version. A later valid Save changes for the same report returned HTTP 500. The rendered page showed a safe generic problem; the report version, content, and audit count did not change. Server logs identified a unique constraint on `notification(user_id, kind, subject_id)` during `notifyReportChanged`: repeated `report_modified` notifications for the same recipient and report collide. [Redacted response and database observations](repeat-edit-defect.json) contain no raw request body or record ID.

## Local recovery behavior

On the second synthetic report, the browser deliberately returned HTTP 503 for one autosave request. The app kept a local draft without writing to the database. After reload, Recover draft restored the pending text on the same version without saving it. A second Owner browser context then saved a newer server version (HTTP 200). After another reload, Recover draft was disabled, the warning explained that the local version was older, Compare showed the pending text, and Discard cleared only local storage. The newer server record and audit count stayed unchanged by recovery, comparison, and discard. [Redacted recovery results](local-recovery-results.json) and a cropped warning screenshot document this path.

All evidence was scanned for credentials, account addresses, session data, and record IDs. Screenshots show only synthetic notices and controls. The disposable preview and database were removed after the probe.

After the recheck, the 4174 preview was stopped, its disposable database, documents, and temporary scripts were removed, and port 4174 had no listener. The shared Playwright fixture pointer and lock were never used by this independent run.
