# Supplier Coordinator stale Time submission: browser baseline

Actual headless Chromium against isolated candidate commit `a21d12d0383b149170da7a6d3faad70bde37a5b2` on 27 September 2026. Playwright created a fresh disposable database and supplier role/grant scaffold. The Supplier Coordinator signed in through the rendered login form and created each Time draft through the rendered Supplier form. Two authenticated tabs then made competing changes through the UI. No production account, record, or deployment was touched.

The reproducible [browser case](baseline.spec.ts) passed **2/2** at **390 × 844 English** and **1440 × 900 Portuguese**; two nonmatching project instances were intentionally skipped. Read the [phone trace](results-phone-390.json), [desktop trace](results-desktop.json), [phone changed-draft notice](changed-phone-390-en.png), and [desktop changed-draft notice](changed-desktop-pt.png). The screenshots contain only the generic error notice. Traces omit account identities, record IDs, draft summaries, session data, and raw responses. Both tabs had zero page exceptions and unexpected console errors.

The Report workspace and locale remained selected. In the changed-draft case, focus landed on a warning `aside` in the draft form while the error notice was above the viewport (phone −621 to −540 px; desktop −763 to −682 px). Window scroll moved from 0 to 1004 px on phone and 1085 px on desktop. In the already-submitted case, the error notice itself received focus, but its top was 0 px under the sticky header ending at 70/72 px. Window scroll moved from 0 to 383/322 px. Notice geometry was captured **before** screenshot calls, which can scroll an element. Already-submitted screenshots were excluded because the sticky header covered their notice and included account chrome.

The known database rules are distinct: `Time entry changed before submission`, `Time entry is not a draft for submission`, and `Time entry locked before submission`. The Supplier action mapper still lists an older combined message, `Time entry changed or cannot be submitted`, so these current conflicts reach the shared generic fallback without a permitted next step. The existing [Supplier consequence-warning browser run](../lifecycle-supplier-warnings/README.md) covers successful single and batch submissions, not stale submissions.

This run covered the Supplier page's native form actions. It did not exercise a JavaScript-enhanced Supplier submission or batch atomicity. The disposable fixture pointer and lock and port 4174 were released after the run.
