The closeout page started at `scrollY=500`; the candidate moved to 314 px on phone and 310 px on desktop so the notice begins 12 px below the sticky navigation. The focused control, chosen draft, and surrounding form remain visible. The desktop technical-report invalid edit settled back to its original 480 px scroll position after a native form navigation. Its diagnostic trace shows a brief initial `scrollY=0` during page load before restoring 480 px. This is a visual polish risk, not a failed settled-state assertion. No candidate page errors were captured.

The role-specific closeout 403 wording and problem-notice positioning were gaps in the first candidate browser run. Both were fixed during this QA pass. The final focused run passed 8 cases and 2 viewport skips, validating the updated copy and full notice visibility. Production still runs the earlier deployed version and has not been altered by this QA lane.
