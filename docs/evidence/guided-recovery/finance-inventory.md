# Finance and Owner finance recovery inventory

Inspected 2026-10-08 in the shared Client Essential worktree. This inventory names actual rendered tasks and server actions. Owner/Admin and Finance/Admin own financial decisions; Auditor can inspect but cannot submit. Worker and PM recover operational approval/corrections in their own queues, with no commercial rates or cost projections exposed.

The shared guided recovery reads `ProblemData.fieldErrors`, the submitted `actionName`/`billingOperation`, and the actual enabled form controls. Money forms store exact minor units in hidden fields and edit the visible `[data-minor-target]` decimal control. Each repair must retain the other values and submit through the existing audited action after final review.

## Implemented defects and verification boundaries

Project-native Finance forms extend this inventory with `saveProjectPersonDefaults` in `ProjectEconomicsDefaults` and `saveBillingSetup`, `savePersonTerms`, `savePeopleTerms` in `ProjectBillingSetup`, at `/app/projects/{id}?tab=billing`. Their missing fields cover effective dates, customer sale rates/unit, separate internal cost, worker pay/percentage, payer/reimbursement/customer recovery, issuer/cadence/template settings and source/version fingerprints. The shared recovery bridge retains `values`, maps legacy `fields` plus indexed batch errors, and uses the actual normal form. Visible person draft controls explicitly identify their individual and batch forms; applying repairs updates bound drafts before the ordinary audited save. Source/version conflicts return to the current project instead of overwriting prior terms.

- Approved invoice reservation now has its own status; draft/approved sources remain separately reserved and duplicate-safe.
- Diagnostic actual time counts the original while a pending correction blocks billing, and only its approved replacement after approval. Nearby dates exclude superseded originals, pending corrections and active invoice reservations.
- Generic time correction resets billability to pending, clears approval-derived Finance markers already handled by the correction mapper, and records `financeReviewRequired` in its existing audit event. Neither checking a period nor fixing a missing rate approves time.
- Both readiness and draft generation accept cadence boundaries clipped to inclusive effective dates. A stream effective from the 15th includes work on the 15th. Automatic UI alignment discloses entered and selected dates before draft creation; draft source queries continue using the exact reviewed period.
- Missing customer rate identifies actual dates and links directly to authorized Client labor rate form. Copying an existing hourly sale amount requires a consent checkbox and prepares the separate internal cost form; ordinary save, validation and audit remain mandatory.
- All visible forms rely on the shared guided recovery integration owned by the root agent. Local Finance/browser evidence and integration test outcomes are reported in the handoff; this document alone is not runtime proof.

Focused regression coverage: `billing-mag-period-readiness.test.ts`, `billing-period-recovery.test.ts`, `billing-guided-rate-recovery.test.ts`, existing `approval-lifecycle.test.ts`, billing validation/retention suites, and `finance-guided-recovery.browser.spec.ts`. No production database or financial history was mutated.
