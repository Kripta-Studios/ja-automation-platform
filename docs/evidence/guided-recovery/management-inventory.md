## Global dialog attachment and discovered gaps

`ProblemNotice` sends the shared recovery request; native constraints are handled globally. The existing action runs only after the explicit final review/confirmation. Hidden/disabled/read-only/password/file controls cannot become editable dialog fields. State, permission, stale version, unavailable service and unknown-save-outcome errors offer existing allowed review links. Configuration must be changed in its authorized existing form; recovery must not fabricate activation, role, version, credential, request key, or financial history changes.

Confirmed/fixed in this lane: client-directory contact native rejection lost values and closed the originating editor; contact update lacked schema-level email/phone validation; unchecked primary/billing flags lacked presence markers; project-linked contact deletion used a generic conflict; local account and supplier fallback metadata lacked common action identity; initial supplier roster type erased name/date fields needed by the authorized UI; Team initial filters lacked `untrack` import. Focused tests caught an intermediate Zod default-on-partial issue; final code validates partial input while preserving omitted-field semantics.

Forwarded to integration owners: query-preserving action URLs require the shared matcher to recognize `&/action` and exact record IDs; project finance defaults/billing/person terms and unused issuer replacement use plain failure summaries, AccountingPack artifact retries use local direct-fetch notices; Timesheet/ExpenseWeek use enhanced local errors; auth, passkey and optional MFA failures use client-local messages. These require explicit event adapters or safe informational routing where no editable field exists. Root owns auth/security adaptation, finance owns commercial/artifact adaptation, operations owns weekly forms. Source presence alone does not prove those bridges work.
