# Deployed-app browser audit — 2026-09-29

## Scope and method

The team exercised https://j-aautomation.com/j-aautomation/app in Chromium with the manual's six test accounts and the Owner account supplied by the requester. GPT-6 Luna agents performed the subsequent operational and finance browser checks; GPT-6.1 Sol guided them, implemented fixes and reviewed the candidate independently. Earlier exploratory agents' findings were handed to that team.

Playwright MCP and standalone Playwright drove visible controls, actual form submissions, reloads and downloads. Chromium DevTools Protocol `Network` and `Runtime` domains were enabled. The team checked responses, page exceptions, console output and storage key names. Authentication state, passwords, raw production screenshots, traces and response bodies remain private outside Git. No intercepting proxy was necessary because the available Playwright/CDP tools provided runtime inspection.

Production writes were restricted to clearly named synthetic QA projects and records. Invoice issuance, payments/reversals, configuration experiments and full lifecycle regressions used a separate disposable SQLite fixture. Issued production invoices and financial history were not changed.

### Automatic recovery and unresolved errors

Known state is recovered without interrupting the user: tab and filter state, explicit sort order and the selected week are restored automatically. Existing editable expense and issuer defaults remain automatic. Invalid recipient email retains its entered value, returns to the relevant wizard step and focuses the field with its linked message. Concurrent financial revisions and a missing compatible issuer retain actionable warnings because overwriting financial changes or inventing legal details would require information the app does not have.
