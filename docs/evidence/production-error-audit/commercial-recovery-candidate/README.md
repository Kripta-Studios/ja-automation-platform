# Commercial form recovery candidate

Production Finance browser observations on 26 September 2026 are recorded in [the Finance audit](../finance/README.md). Eight rejected Commercial submissions returned specialized problem codes. Several native responses lost the selected task or scroll position; the issuing revision disclosure closed. Those observations were made against the deployed build, before this candidate change.

The candidate keeps the Commercial view and selected project in each Commercial POST action URL. It restores the failed task, conditional controls, visible amount inputs and their submitted canonical values. The Finance response handler now matches forms using fixed hidden record IDs, then restores entered values and puts keyboard focus on the visible field error. If an overtime threshold arrives after overtime was turned off, the error appears beside the visible overtime choice.

Disposable Chromium regression: [commercial-form-recovery.spec.ts](../../../../tests/e2e/commercial-form-recovery.spec.ts). Finance Administrator submitted invalid forms at **390 × 844** and **1440 × 900**. The two initial policy and compensation scenarios passed at both widths. A follow-up run covered all six other Commercial actions from the production audit at both widths: issuing revision, project issuing authority assignment, project reimbursement default, settlement snapshot, customer labor rate, and internal loaded cost. The follow-up passed **2/2 viewport tests, 12/12 action steps**.

Checks covered the specialized problem code, retained Commercial task and relevant entries, issuing revision disclosure, field error and keyboard focus, scroll after rejection, and no horizontal overflow. Database assertions confirmed no revision, assignment, settlement, labor rate, internal cost rule, or reimbursement project update for the rejected submissions. The stale issuer-option and malformed-date cases deliberately relaxed a client control to reach server validation; they did not write business data. A malformed date cannot be represented in a native date input after reload, while valid entries in that form were retained. Portal typecheck and `git diff --check` passed.

The candidate has not been deployed to production. The deployed behavior should be checked again after release using an authorized read-only or deliberately invalid workflow. Success, stale-record conflict, and role-denial paths for these six actions were outside this focused failure-recovery check.
