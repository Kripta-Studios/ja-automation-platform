Observed 26 September 2026 UTC in a separate authenticated Owner browser tab on the deployed portal, at 390 × 844 and 1440 × 900. Source checkout HEAD while observing was `8669fa3`; this does **not** identify the deployed release or verify the candidate build. The browser console contained only the expected failed-resource entry for each rejected HTTP 400 navigation; no JavaScript exception was observed. Notice-only screenshots are intentionally cropped to exclude names, credentials, record identifiers and unrelated customer data. Element screenshots scroll the notice into view, so they document the wording; the recorded focus coordinates above document the recovery defect before screenshot capture.

This shows a shared native-form recovery problem: focus moves to the summary while scroll restoration can leave that focused summary off-screen. The candidate Planning and Documents fixes still require actual browser verification at both widths before release.
