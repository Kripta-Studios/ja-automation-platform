## P2 — Availability ordering error exposes an input bound, not the rule

On `/app/profile` → Add availability, setting Start to **2026-10-02 09:00** and End to **2026-10-01 09:00**, then Save, gave the following at 390 px for Worker 1 and Project Manager:

- EN: `Ends: Enter a value of at least 2026-10-02T09:00.`
- ES: `Termina: Introduce un valor igual o superior a 2026-10-02T09:00.`
- PT: `Termina: Informe um valor maior ou igual a 2026-10-02T09:00.`

The browser blocks POST, focuses End, retains both date values, and leaves the editor open. The text uses a raw datetime control value. A clearer localized rule is “End must be later than Start (2 October 2026, 09:00). Change the End time.” The [cropped phone screenshot](availability-end-before-start-390.png) shows the current copy. No production availability was saved.

## Coverage boundary

The sampled manager/worker scopes contain no authorized projects or records. Therefore this production pass could not exercise a status changing while a form is open, duplicate assignment, submitted/approved time or expense states, linked meal rules, report correction, or a successful write. Prior synthetic project evidence is historical and cannot be treated as current release evidence. The [sanitized form survey](survey.json) and [validation observations](validation.json) record what was actually available. A disposable seeded browser environment is needed for those state transitions; production tests should continue without business writes.
