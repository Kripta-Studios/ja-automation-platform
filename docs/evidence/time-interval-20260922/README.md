## Behavior implemented in the current tree

- **Actual time, CORE-04:** Log time starts with today's date in the browser's local timezone, remains editable, and records same-day start/end clocks in the project's local timezone. An optional break is subtracted to calculate net duration. Clock values remain wall-clock values; they are not silently converted to UTC. Ordinary and supplier time entry/edit paths, server parsing, canonical validation and offline payload handling carry the existing interval columns.
- **Legacy meaning:** Existing duration-only entries keep their recorded duration and no clocks are invented. Adding actual clocks requires the editable draft or authorized correction path. The new form requires positive net duration; report validators also preserve valid historical zero-net entries whose break covers the entire positive same-day interval. Invalid clock pairs, reversed/equal clocks, excessive breaks and contradictory net minutes are rejected at report snapshot boundaries.
- **Operational reports and private worker statements:** New snapshots carry optional `startTime`, `endTime` and `breakMinutes` only when source clocks exist. Period customer/internal web details and PDFs, worker statement web/PDF/CSV, and supplier operational web/CSV/print views show recorded intervals alongside net duration. Legacy snapshots remain duration-only. Customer DTOs remain operational and money-free; worker statements retain their own-account boundary. Daily and Technical / PLC narratives do not acquire an invented association to a time entry.
- **History:** Finalized period snapshots and previously stored worker statement snapshots are not rewritten by later source changes. No issued historical file is regenerated as part of adding interval display. Existing database columns are reused; this packet adds no migration. Exact-money calculations, commercial rules and permission boundaries remain authoritative.
- **Entity pickers:** Search is integrated into the dropdown rather than a second permanent input above it. Keyboard selection, cancellation without changing the native value, accent/case-insensitive matching, native fallback, disabled-option behavior and form submission are covered by dedicated browser specifications. These are implementation/test-scope statements; final browser completion is still pending below.
- **Register filters:** Time and Expenses use a shared wrapping active-filter summary, counts and a clear action only when criteria exist. Reset clears saved search/order/page state. Filtered-out rows receive a no-match message instead of a claim that no records exist. Reports use one authoritative filter/sort model for their registers, with appropriate status/worker scope; the shared RecordBrowser avoids duplicate controls and hides unusable single-page navigation. Creation and record lifecycle actions remain available according to role.
- **Manual sources:** Six functional guides in EN/PT-BR and three employee quick guides in EN/ES/PT-BR explain the new clock semantics, optional break, net duration, legacy fallback and report history. UTC instructions are scoped to planning/availability. The worker time-entry screenshot marker and caption/capture support are present; final captures and generated PDFs remain pending.
