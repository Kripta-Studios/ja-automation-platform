Access · activate the invitation and sign in

Go here: Your trusted invitation → Activate your account → Return to sign in → Profile

Do the task

  1. Check the portal address and named account against the invitation provided by the Owner. There is no public sign-up. For an already provisioned account, use the sign-in method supplied to you; do not attempt to activate someone else’s invitation.
  1. For a single-use activation link, open Activate your account. Enter Full name and choose a Password of at least 12 characters, then Activate account. Wait for Account activated. You can sign in now. Do not repeatedly submit while Activating… is displayed.
  1. Choose Return to sign in. Enter your account Email and Password and select Continue to workspace. If you previously enabled MFA, complete Verify your identity with the current Six-digit code and Verify and continue. Use a recovery code only through the offered Use a recovery code control.

Verify the result

  • For an incorrect password, inactive account or lost access, contact admin@j-aautomation.com from your verified account/contact channel. Supply identity and the visible error; never send the password. This guide does not promise a public password-reset form. Isolated readiness lab · actual own weekly expenses, receipt attachment and returned expense correction
Go here: Expenses → Enter a week in a table → Save weekly expense drafts → Edit → Submit this week

The weekly table saves up to one purchase per worked day for one project and your own account. Choose the project and week first; changing either can clear unsaved rows after confirmation. Enter actual category, amount, currency, payer, vendor and description. The exact save button is Save weekly expense drafts.

The tested October 10 and 11 purchases were USD 5 and USD 7. Each saved draft was opened with Edit, its own matching receipt was attached with Save changes, and the displayed October 5–11 week was then submitted. Two drafts became Submitted and zero remained.

Missing receipt rules are state-specific. The deployed weekly table creates receipt-optional drafts; an earlier USD 5 + USD 7 set therefore submitted without receipts. Where a saved draft requires a receipt, the weekly UI disables Submit this week and the repository validates the whole set. That required-missing saved-draft branch was source-checked, but was not created through a supported native control in this lab. Attach the required evidence rather than assuming every receipt-free draft is blocked.

Do the task

  1. Open each saved draft through Edit, use Attach receipt (optional), select the correct date/amount receipt and Save changes. Reopen the exact expense to verify Registered private receipt.
  1. Choose the intended Week containing → Show week. Inspect every included draft and use Submit this week. Confirm each record’s Submitted state and the remaining count.
  1. For a returned expense, read Review reason and use Create corrected draft when offered. Review all values and the receipt: leave the attachment empty to retain the original receipt, or attach its genuine replacement. Create the linked draft, inspect it, then Submit.

Verify the result

  • Actual October 10/11 receipt-backed submission: exactly two expense IDs, USD 5 + USD 7, each with its own registered receipt, both Submitted and zero remaining drafts.
